# Реализация первого выпуска

Стек: Node.js 24.19+, TypeScript, Express, встроенный `node:sqlite`, React + Vite. Отдельная служба `shorts-panel`; данные не смешиваются со Stream Panel. Приложению нужен `ffprobe` из FFmpeg для проверки загрузок. Тяжёлого перекодирования нет.

## Реализовано

- Парольный вход, серверные сессии, CSRF и проверка Origin; cookie HttpOnly/SameSite, Secure при HTTPS. Публичной регистрации нет.
- Локальная потоковая загрузка MP4, проверка вертикального формата и длительности 3–180 секунд, размер до 1 GiB. Контроль дискового бюджета и резерва; одна загрузка одновременно.
- Постоянная SQLite-очередь, недельное балансирование, сохранение порядка, ручная перестановка, произвольное закрепление контента/рекламы.
- Календарь дня/недели/месяца, реальные статусы площадок и просмотр исходника.
- Три задания на ролик, льготный час, независимое догоняние, резерв 01:00, хранение до последнего подтверждённого успеха +24 часа.
- OAuth-конфигурация и подключение Google/Instagram; токены и Client Secret шифруются AES-256-GCM на сервере. Ключ хранится отдельно от SQLite в закрытом каталоге данных.
- Адаптер YouTube: resumable upload и проверка обработанного public-видео. Адаптер Instagram: контейнер, проверка обработки, публикация и permalink.
- Явное состояние неопределённого результата. При сомнении автоматический повтор запрещён, чтобы не создавать дубликаты. Пользователь проверяет отсутствие поста перед разрешением повторной отправки.
- Явный отказ авторизации (HTTP 401, OAuth invalid_grant/invalid_client, Instagram code 190) сохраняет статус повторного подключения, не удаляя токены и внешние ID. Временные ошибки не отключают аккаунт; обновлённый refresh token YouTube сохраняется при ротации. Успешное новое подключение снимает предупреждение.
- HTTP 429 учитывает Retry-After в секундах или HTTP-date. Пауза всей площадки сохраняется в SQLite; другие площадки продолжают работу. Некорректное/прошедшее значение означает минутную паузу. Если ожидание выходит за исходный льготный час, публикация переносится в доступный слот догоняния.
- Истёкшая resumable-сессия YouTube (404/410) сохраняется как требующая проверки. Новая загрузка разрешается только после явного подтверждения отсутствия поста; действующая сессия и известный ID при ручном повторе сохраняются.
- TikTok отображается как неподключённый; публичный Direct Post не имитируется.
- После окончательного отказа обработки YouTube или ERROR/EXPIRED контейнера Instagram подтверждённый ручной повтор создаёт новую загрузку/контейнер. До проверки отсутствия поста старые ID сохраняются; другие площадки не сбрасываются.
- Начатая отправка сохраняет ID целевого аккаунта. Переподключение другого канала при незавершённых привязанных публикациях отклоняется; отключение/новый OAuth не стирают привязку. Это не перенос очереди между каналами.
- Ответы refresh/OAuth и отказы авторизации сверяются с актуальной конфигурацией и токенами: запоздавший запрос не восстанавливает отключённый аккаунт и не затирает/отключает новое подключение. После смены подключения новые шаги старой операции прекращаются, уже полученные внешние ID сохраняются.
- Незарегистрированные MP4 и завершённые .part можно восстановить офлайн командой `npm run recover` с явным названием и хэштегами. Общая проверка формата используется и при загрузке, и при восстановлении; работающий worker блокирует восстановление.

## Технические решения для прежних открытых вопросов

Это принятые при реализации обратимые решения, не дополнительные ответы владельца:

- Задание фиксируется в момент наступления общего планового времени; предварительная отправка в нативный график YouTube пока не используется.
- Восстановление использует ближайший свободный из 01/06/12/17 отдельно для площадки; общий план имеет приоритет. Среди доступных долгов — более раннее время попытки.
- Одинаковое точное время ручного закрепления двух роликов отклоняется. Отдельный минимальный интервал не введён.
- При ручной перестановке прежнее время нового первого ролика не считается неприкосновенным.
- Общий календарь считает наступившие задания покрытием дня независимо от отставания отдельной площадки.
- Временная потеря прав/сетевой результат, который нельзя надёжно классифицировать, переводятся в ручную проверку. Это консервативнее автоматических повторов; классификацию безопасных повторных ошибок нужно расширять после живых API-тестов.

## Ограничения

Настоящие OAuth/публикации не проверены без приложений и аккаунтов владельца. Нет обещания полной готовности автопостинга. Для TikTok нужен выбранный допустимый способ доступа. Заморозка площадки и автоподбор хэштегов отложены. Пока поддерживается один парольный пользователь и один канал каждой площадки.

Время публикации инициируется сервером; обработка у соцсети занимает дополнительное время. Переподключение API в каждый пост не требуется, но отзыв/истечение доступа нужно обслуживать.

## Локальный запуск

```sh
npm ci
npm run build
# Прочитать пароль без отображения и передать через stdin, не в argv/history.
read -r -s -p 'Новый пароль (14+ символов): ' SHORTS_INITIAL_PASSWORD
printf '%s' "$SHORTS_INITIAL_PASSWORD" | npm run provision
unset SHORTS_INITIAL_PASSWORD
SHORTS_PUBLIC_ORIGIN=http://127.0.0.1:47921 npm start
```

Приложение доступно на 127.0.0.1:47921. Для Vite dev-server запускать backend с `SHORTS_PUBLIC_ORIGIN=http://127.0.0.1:5173`, затем `npm run dev`. Пароль, ключ шифрования и база находятся в `SHORTS_DATA_DIR` (по умолчанию `data/`, исключён из Git).

Проверки: `npm run check`, `npm test`, `npm run build`, `node --import tsx scripts/smoke.ts` после установки браузера Playwright. Smoke использует временную базу и сгенерированный тестовый ролик, не реальные аккаунты.

## Контрактные проверки и полный gate

HTTP-приложение создаётся отдельно через `createApplication`; тесты не запускают фоновый таймер и не обращаются к настоящим аккаунтам. Сохраняются реальные SQLite, сессии и файловые операции. Провайдеры проверяются подменой сетевых ответов, UI — Playwright с реальной загрузкой и дополнительными сценариями отказа. Проверка метаданных выделена в `media.ts`.

`npm run coverage` строит временную инструментированную UI-сборку, объединяет серверное и браузерное покрытие, проверяет минимум 90% строк/ветвей/функций/statements и восстанавливает обычную сборку. Нужны `ffmpeg`, `ffprobe` и Chromium (`npx playwright install chromium`). Все численные результаты и остающиеся ограничения — в `development-plan.md`.
