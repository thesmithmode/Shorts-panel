# Подключение YouTube, TikTok и Instagram

## Статус исследования

Ни один реальный аккаунт в новый проект ещё не подключён. Здесь сохранены результаты обсуждения API и ссылки на официальные источники. Реальное право публикации, квоты и доступность функций необходимо проверять на аккаунтах владельца перед обещанием полного автопостинга.

Платформенные правила изменяются; перед реализацией перепроверить источники. Согласованная продуктовая логика не означает, что платформы разрешают её в любом приложении.

## Общий принцип OAuth

Владелец один раз нажимает подключение, входит на официальном сайте площадки и даёт нужные разрешения. Пароли от соцсетей панель не собирает и не хранит. Сервер хранит токены и продлевает доступ автоматически, пока это допускается платформой.

Повторный вход может понадобиться при отзыве прав, истечении долгосрочного доступа, проверках безопасности, изменении разрешений или ошибках обновления токенов. Нельзя обещать вечное подключение, но вход перед каждым роликом не нужен.

OAuth-приложения, секреты и URL возврата настраиваются однократно. Для production нужен HTTPS callback. Приватная панель не должна закрывать cookie-авторизацией те адреса файла/callback, к которым платформам необходим доступ; реализацию ограничений определить отдельно.

## YouTube

В Stream Panel уже есть Google OAuth, но по README он использует read-only scopes. Они не дают права загружать ролики. Для Shorts Panel понадобится соответствующее разрешение, например `youtube.upload`, и подтверждение владельца в Google. При отдельном OAuth client подключение отдельное.

Шаги настройки:

1. Создать либо выбрать Google Cloud project и включить YouTube Data API v3.
2. Настроить OAuth consent screen и Web OAuth client с точным HTTPS redirect URI панели.
3. Настроить production-режим и выполнить применимые требования Google к верификации. Production-режим не равен завершённой верификации.
4. Запросить offline access и право загрузки, выбрать нужный YouTube/Brand-канал.
5. Сохранить refresh token на сервере и проверить загрузку/публикацию настоящего тестового ролика.

В режиме внешнего OAuth-приложения **Testing** refresh token для YouTube-разрешений обычно истекает через **семь дней**. Это не подходит для постоянной автономной очереди. В рабочем режиме сервер может обновлять короткоживущий access token без участия пользователя.

YouTube поддерживает нативное расписание `status.publishAt` для private-видео, которые ранее не публиковались. Ранняя загрузка потенциально повышает устойчивость к сбою VPS, но наша очередь может менять время и порядок. Поэтому решение о моменте отправки в YouTube и границе, после которой план уже нельзя свободно пересчитывать, пока открыто.

При исследовании актуальная страница `videos.insert` указывала, что загрузки unverified API projects не ограничиваются private, тогда как старые записи revision history содержали прежнее ограничение. Не переносить устаревшие утверждения без перепроверки текущего правила и живого теста.

Источники:

- [YouTube: videos.insert, разрешения загрузки](https://developers.google.com/youtube/data/reference/rest/v3/videos/insert).
- [YouTube: ресурс video, status.publishAt](https://developers.google.com/youtube/data/reference/rest/v3/videos).
- [Google OAuth: offline access](https://developers.google.com/identity/protocols/oauth2/web-server).
- [Google OAuth: причины истечения refresh token и Testing](https://developers.google.com/identity/protocols/oauth2).

## Instagram

Нужен профессиональный аккаунт **Creator или Business**. Обычный личный аккаунт для публикации через этот API не подходит.

Предложенный путь — **Instagram API with Instagram Login**, без обязательной привязки Facebook Page. Альтернативный Facebook Login требует связанную Facebook Page; не смешивать разрешения и токены двух вариантов.

Для Instagram Login требуются как минимум `instagram_business_basic` и `instagram_business_content_publish`.

Шаги настройки:

1. Проверить/перевести нужный аккаунт в Creator либо Business.
2. Создать Meta app с продуктом Instagram и выбрать Instagram Login.
3. Настроить redirect URI и доступ/роли собственных подключаемых аккаунтов.
4. Войти через Instagram, выдать разрешения и обменять токен на долгоживущий.
5. Настроить фоновое продление и выполнить реальный тест Reels.

Для собственных аккаунтов с ролями приложения исследовался Standard Access; для обслуживания сторонних аккаунтов может потребоваться Advanced Access, App Review и Business Verification. Реальные требования подтвердить в кабинете Meta.

В обсуждении зафиксирован цикл: короткий токен → долгоживущий примерно **60 дней** → автоматическое продление до истечения. Это не требование вручную логиниться каждые 60 дней. При исследовании страницы Meta о токенах вернули 429/ошибку доступа; срок, условия продления и доступ нужно дополнительно проверить по актуальной документации и реальному ответу API.

Публикация Reel включает создание контейнера, передачу/получение видео, ожидание готовности и финальную публикацию. В варианте `video_url` Meta скачивает файл по доступной ей HTTPS-ссылке. Готовый контейнер не равен опубликованному посту.

Источники:

- [Официальная коллекция Instagram API от Meta](https://www.postman.com/meta/instagram/documentation/6yqw8pt/instagram-api).
- [Instagram Login и publishing scopes в коллекции Meta](https://www.postman.com/meta/instagram/documentation/6yqw8pt/instagram-api?entity=request-23987686-3fe78620-2258-44b6-893f-42d76c7200d7).
- [Instagram API with Instagram Login](https://developers.facebook.com/docs/instagram-platform/instagram-api-with-instagram-login/).
- [Meta: refresh_access_token](https://developers.facebook.com/docs/instagram-platform/reference/refresh_access_token/).

## TikTok — нерешённая зависимость полного автопостинга

Content Posting API Direct Post существует, но unaudited-приложения ограничены приватными публикациями и тестовыми условиями. Для публичного Direct Post нужен аудит приложения.

Ключевой риск: официальные Content Sharing Guidelines прямо приводят приватную утилиту загрузки в аккаунты владельца/его команды как недопустимый intended use. Поэтому нельзя обещать, что самостоятельная личная панель получит публичный Direct Post после обычной регистрации OAuth.

Варианты, рассмотренные в обсуждении:

1. Одобренный посредник с API автоматической публикации. Проверить реальный Direct Post, доступность для аккаунта, условия, частоту, стоимость и поддерживаемый сценарий расписания. Посредник пока **не выбран**, покупка не согласована.
2. Собственный Direct Post только после подтверждения допустимого пути доступа. Не выдавать приватный тест за рабочую публичную интеграцию.
3. Upload API с завершением публикации владельцем в приложении TikTok — требует scope `video.upload` и одобрения приложения. Это **не полноценный автоматический постинг** и не удовлетворяет целевому сценарию без дополнительного решения владельца.

У собственного OAuth TikTok access token действует примерно **24 часа**, refresh token — до **365 дней** по документации. Короткий токен можно обновлять без участия пользователя. Сохранять новые значения и реальные сроки из ответа API, учитывать ротацию токенов.

Источники:

- [TikTok: Content Sharing Guidelines и intended use](https://developers.tiktok.com/docs/en/content-sharing-guidelines).
- [TikTok: Direct Post prerequisites](https://developers.tiktok.com/docs/en/content-posting-api-get-started).
- [TikTok: Upload с ручным завершением](https://developers.tiktok.com/docs/en/content-posting-api-get-started-upload-content).
- [TikTok: управление access/refresh token](https://developers.tiktok.com/docs/en/oauth-user-access-token-management).

## Общие эксплуатационные ограничения

Нужно учитывать обработку видео, квоты, ограничения частоты и права на музыку/контент. Панель не обязана воспроизводить весь редактор мобильных приложений. Никакие реальные токены, секреты и видео в документацию или Git не переносить.


## Повторная проверка официальных источников — 2026-11-03

- **YouTube:** актуальный справочник `videos.insert` указывает отдельную квоту загрузок по умолчанию 100 вызовов в день и отмечает, что неверифицированный API-проект сам по себе больше не ограничивает все загрузки приватным режимом; настройки конкретного аккаунта и доступный лимит нужно проверить отдельно. Источник: [YouTube videos.insert](https://developers.google.com/youtube/data/reference/rest/v3/videos/insert). У внешнего OAuth-приложения в режиме Testing refresh token для этих разрешений обычно истекает через 7 дней: [Google OAuth](https://developers.google.com/identity/protocols/oauth2).
- **Instagram:** в официальной коллекции Meta для Reels перечислены H.264/HEVC, 23–60 FPS, ширина не более 1920 пикселей, видео до 25 Мбит/с, звук AAC 48 кГц, MP4/MOV и ограничения размера/длительности. Это требования платформы, а не утверждение, что текущий валидатор проверяет каждое из них: [Reels Publishing](https://www.postman.com/meta/instagram/folder/830j7my/reels-publishing). До реального теста учитывать различия вариантов Instagram Login и Facebook Login.
- **TikTok Direct Post:** действующие правила по-прежнему называют частную утилиту для управляемых владельцем аккаунтов недопустимым применением, требуют аудита для публичной видимости и пользовательского выбора настроек публикации: [Content Sharing Guidelines](https://developers.tiktok.com/docs/en/content-sharing-guidelines). Они также предписывают для уже находящихся на сервере файлов использовать PULL_FROM_URL с подтверждённым доменом или URL-префиксом; URL должен быть HTTPS и не перенаправлять. Возможность верифицировать конкретный адрес sslip.io не подтверждена: [Media Transfer Guide](https://developers.tiktok.com/docs/en/content-posting-api-media-transfer-guide).
- **TikTok API for Business — отдельная гипотеза:** в официальном описании Accounts API перечислена публикация видео для бизнес- и личных аккаунтов, а для доступа указана предварительная заявка. Это другой продукт и не доказательство, что личная панель владельца получит доступ либо что требования Direct Post к нему применимы или не применимы; нужно отдельно выяснить право доступа, требования аккаунта, публичность и лимиты: [Accounts API Overview](https://business-api.tiktok.com/portal/docs/accounts-api-overview/v1.3). Посредник, платная подписка и новый домен не выбирались.
