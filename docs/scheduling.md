# Правила планировщика

## Время и окно — согласовано

- Все пользовательские даты, слоты и границы дней определяются по **Europe/Moscow**.
- Обычные слоты: **06:00, 12:00, 17:00 МСК**.
- Резервный **01:00 МСК** предназначен только для догоняния пропущенных публикаций конкретной площадки. Новая общая очередь его не занимает.
- Целевой горизонт — ближайшие **семь календарных дней**, а не произвольные 168 часов.
- Сегодня входит в горизонт, если остался хотя бы один будущий обычный слот. Если все обычные слоты прошли, ближайший день планирования — завтра.
- Прошедшие слоты не используются для назначения новых роликов. Повторные попытки старых публикаций регулируются отдельно.
- Уже опубликованный сегодня обычный контент засчитывается в заполнение сегодняшнего дня.

Хранение timestamp в UTC с переводом в Europe/Moscow — предложение реализации. Границы дней нельзя вычислять по локальному часовому поясу VPS или браузера.

## Приоритет распределения — согласовано

1. Учитывать неподвижные ручные закрепления и уже опубликованные ролики.
2. Сначала обеспечить хотя бы один обычный ролик в каждый доступный день семидневного окна, насколько хватает видео.
3. Если на все дни уже есть по одному, распределять вторые ролики по дням.
4. Только затем распределять третьи.
5. На полных будущих днях дополнительные ролики получают сначала более ранние дни. Для частичного сегодня, закреплений и неподвижного ближайшего ролика учитывать доступность времени.
6. Если роликов больше обычной вместимости семидневного окна, остаток плотно занимает последующие дни: первый доступный обычный слот восьмого дня, затем второй, затем третий, затем девятый день и далее.

Нельзя планировать три ролика в одном свободном будущем дне, оставляя другой день целевого окна без обычного контента, если очередь можно перераспределить без нарушения более приоритетных ограничений.

При двух роликах на полном дне выбирать **06:00 и 17:00**, а не 06:00 и 12:00. При трёх — 06:00, 12:00 и 17:00. Для частичного сегодня или закреплённого времени не назначать прошлое и не сдвигать защищённую публикацию ради этого шаблона.

## Примеры на полном свободном окне

Все семь дней имеют три доступных обычных слота; нет закреплений, опубликованного контента и исключений.

| Число роликов | Дни 1 → 7 | За пределами недели |
| --- | --- | --- |
| 1 | 1 · 0 · 0 · 0 · 0 · 0 · 0 | Нет |
| 6 | 1 · 1 · 1 · 1 · 1 · 1 · 0 | Нет |
| 7 | 1 · 1 · 1 · 1 · 1 · 1 · 1 | Нет |
| 8 | 2 · 1 · 1 · 1 · 1 · 1 · 1 | Нет |
| 9 | 2 · 2 · 1 · 1 · 1 · 1 · 1 | Нет |
| 14 | 2 · 2 · 2 · 2 · 2 · 2 · 2 | Нет |
| 15 | 3 · 2 · 2 · 2 · 2 · 2 · 2 | Нет |
| 18 | 3 · 3 · 3 · 3 · 2 · 2 · 2 | Нет |
| 21 | 3 · 3 · 3 · 3 · 3 · 3 · 3 | Нет |
| 22 | 3 · 3 · 3 · 3 · 3 · 3 · 3 | Восьмой день: 06:00 |
| 23 | 3 · 3 · 3 · 3 · 3 · 3 · 3 | Восьмой день: 06:00, 12:00 |
| 24 | 3 · 3 · 3 · 3 · 3 · 3 · 3 | Восьмой день: все три |

Восьмой день после заполнения горизонта пакуется плотно. Поэтому для 23 роликов его два переполняющих слота — 06:00 и 12:00, в отличие от распределения двух роликов внутри целевой недели. Это следует из подтверждённого описания плотного переполнения; изменение такой политики требует явного решения.

## Порядок и перестановки

У каждого автоматического ролика есть стабильное место в очереди по загрузке. При автоматическом пересчёте порядок сохраняется: новый ролик не вставляется перед старыми только потому, что появился ранний свободный слот.

Например, семь роликов A–G уже стоят по одному в день. При добавлении H день 1 получает A и B, день 2 — C, далее D, E, F, G, H. H остаётся последним, а не публикуется вторым в первый день.

Пользователь может изменить порядок вручную. Это создаёт новый порядок для следующих пересчётов. Ручное закрепление конкретного времени имеет приоритет перед автоматическим распределением; точные конфликты нескольких ручных действий перечислены в открытых вопросах.

## Ближайший ролик

Ближайший автоматический ролик сохраняет назначенное время при пересчёте. Исключение подтверждено владельцем: если на сегодня закреплён **обычный контент**, обеспечивающий заполнение дня, автоматический ролик при нехватке можно перенести на следующий день. Закреплённая реклама такого основания не даёт.

## Течение времени

Целевое окно скользит вслед за московской датой. При уменьшении запаса ролики заново растягиваются по неделе: цель — ежедневное покрытие и равномерная плотность, а не сохранение старой плотной упаковки до опустошения очереди.

Для девяти оставшихся роликов при полном свободном окне целевой результат — 2 · 2 · 1 · 1 · 1 · 1 · 1, а не 3 · 3 · 3 · 0 · 0 · 0 · 0. Неподвижное ближайшее видео и ручные закрепления могут ограничить достижимое распределение.

Автоматический пересчёт нужен при загрузке, смене очередности, закреплении/снятии закрепления и движении времени. Конкретный таймер — деталь реализации. Уже отправленную/обрабатываемую публикацию нельзя молча переназначать: граница фиксации задания ещё требует определения.

## Защита от ошибочных трактовок

- Семь дней — цель покрытия, а не разрешение создать отсутствующий контент.
- 21 ролик — вместимость только полного свободного окна. У частичного сегодня и закреплений вместимость может отличаться.
- Плотность дня не равна числу попыток отправки API.
- Сбой одной площадки не превращает её пропущенный ролик в новый элемент общей очереди.
- Догоняние допускает другой фактический порядок на отставшей площадке; это отдельно согласованное исключение.
